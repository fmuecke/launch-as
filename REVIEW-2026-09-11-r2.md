# launch-as — review: simplicity, complexity, security

Date: 2026-09-11, later the same day · Reviewed tree: current working tree, after the
multi-session rework · Version under review: 1.0.0-preview

Supersedes [REVIEW-2026-09-11.md](REVIEW-2026-09-11.md), which examined the tree as it stood
before the multi-session rework landed and is kept unchanged as the historical record. This is a
standalone review of the current code: every file/line anchor below was re-resolved and every
finding re-read against the on-disk content rather than carried over. Where the rework fixed
something, the finding is kept and marked **RESOLVED** with its residue, so a later refactor
cannot silently reintroduce it.

## Scope and method

Four parallel review tracks over `src/`, `tests/`, `CMakeLists.txt`, the PowerShell
scripts, and the design docs:

1. broker trust boundary (IPC, caller authorisation, untrusted input parsing);
2. credential lifecycle and privileged installation (passwords, ACLs, enrollment, setup);
3. process launch and terminal bridging (ConPTY, job objects, handle inheritance);
4. removable complexity (dead code, duplication, over-generalisation).

### Method caveats

- **No build or runtime verification.** `cmake`, `ninja`, `clang-format`, and the MSVC
  toolchain are all absent from the review environment, and the broker service is not
  installed. Prebuilt binaries under `out/build/` do not match source. Everything except the
  PowerShell quoting defect (item S5, reproduced directly in the earlier review) is confirmed
  by code inspection only.
- **`git` is not on PATH**, so history and tracked-file state could not be queried directly;
  the rework was reconstructed from source, not from a diff. `.gitignore` is exactly `out/`,
  so the release zips and the `out/build/` tree are untracked local artifacts.
- **Physical line counts** (`Measure-Object -Line` skips blank lines; these do not):
  `BrokerProtocol.cpp` 1090, `CMakeLists.txt` 760, `TerminalBridge.cpp` 657,
  `BrokerServiceInstaller.cpp` 656, `BrokerServiceRuntime.cpp` 643,
  `BrokerProcessLauncher.cpp` 569, `BrokerPipeServer.cpp` 406, `PseudoConsoleHost.cpp` 403,
  `BrokerAdminCli.cpp` 305, `PseudoConsoleSession.cpp` 274.

### Effect of the multi-session rework

The earlier review examined a tree in which the multi-session registry had just been reverted.
**It is back, and it is now the specified, implemented, and acceptance-tested design.** What
changed:

- `BrokerServiceRuntime.cpp` grew from 447 to 643 lines. `MaximumConcurrentSessions = 4`,
  `MaximumConcurrentSessionsPerAccount = 2`, `MaximumConcurrentPipeWorkers = 8`
  (`:36-39`), `TryReserveSession`/`ReleaseSession` and the `launchGate` mutex
  (`:109-168`), and a worker pool with overlapped `ConnectNamedPipe` and a bounded wait for a
  free slot (`:258-421`).
- `BrokerPipeServer.cpp` is fully overlapped: every read, write, and child wait is now
  cancellable against `stopEvent`, and the request read has a 5 s timeout
  (`:20-97`). Each connection is served on its own `std::thread`.
- `session_limit_reached` / `ERROR_BUSY` is wired end to end
  (`BrokerPipeServer.cpp:366`, `LaunchProcess.cpp:178-183`).
- New separate `launch-as-admin.exe` target (`CMakeLists.txt:229-265`) with
  `BrokerAdmin.cpp`, `BrokerAdminCli.cpp`, and a real Event Log audit module
  (`BrokerAudit.cpp`). Every ctest registration now carries `LABELS`.
- New acceptance test `tests/Invoke-BrokerSameAccountConcurrencyTest.ps1` (449 lines) proves
  two same-account sessions with distinct logon SIDs, rejection of the third, and that a
  released slot is reused only after the process tree is gone.

**The reset → `LogonUserW` window is still safe, now by an explicit lock rather than by
accident.** `LaunchProfile` holds `policy->launchGate` from before `GenerateBrokerPassword`
through `ResumeThread` (`BrokerServiceRuntime.cpp:506-565`), and `ConfigureProfile` takes the
same gate (`:443`), so enroll/unenroll/list serialise against launches. No reset/logon race was
found. The earlier review's note that "there is now no `std::mutex` anywhere in `src/`" is
obsolete.

Two findings changed grade as a result: **S8** (broker wedge) is now bounded per worker instead
of global, and **C2** (profile unload ordering) is fixed on the production path. One finding was
added: **S12** (session-slot and worker leak on teardown failure), which only exists because
slots exist. And the session-limit documentation mismatch that the earlier review *withdrew* is
back **inverted** — see Documentation defects: `README.md` and `CHANGELOG.md` still promise one
session per account, which is now wrong; the spec is correct.

### S11 — Lower-severity items · CONFIRMED --> FIXED

- **`enroll` silently re-enables a disabled account.** FIXED. `create` fails for an existing
  account; only `create --takeover --force` may re-enable a disabled account. Takeover
  records the SID as launch-as-owned, and `forget` has no account side effects.
- **`unenroll` of one account stops every account's sessions.** FIXED. The public lifecycle no
  longer stops the whole service. `delete` checks the per-account starting/active-session counter
  and returns `ERROR_BUSY`; `forget` only removes metadata.
- **`IsProfileId` control-character rejection.** FIXED.
- **`RevertToSelf` failure returns while still impersonating.** FIXED. The broker now raises a
  process-wide fail-fast exception rather than returning to worker teardown under the caller token.
- **Pipe DACL generic-write grant.** FIXED with an explicit read/write-data mask that excludes
  `FILE_CREATE_PIPE_INSTANCE`.
- **Audit-field injection.** FIXED. The service now shares the protocol profile-name validator
  at both audit call sites and records an invalid value as `<invalid>` rather than interpolating
  it into an audit field.
- **Terminal-pipe DACL built by SDDL concatenation.** FIXED. The bridge now validates the child
  SID and builds a protected ACL programmatically for SYSTEM, the launcher, and the child.
- **`std::wstring_view::data()` passed to `...W` APIs.** FIXED. Win32 null-terminated path
  boundaries now receive owned `std::wstring` copies.
- **Missing hardening.** FIXED. The broker now runs with a restricted service SID and only the
  primary-token assignment, quota-increase, and pipe-impersonation privileges. Native targets
  enable Control Flow Guard, Spectre mitigations, CET compatibility, and system32-only dependent
  loading.
- **`CreateRestrictedToken` (spec `§12`, step 6).** FIXED for the intended privilege-reduction
  scope. After validating the `LogonUserW` token, the broker replaces it with
  `CreateRestrictedToken(DISABLE_MAX_PRIVILEGE)`, requires Medium integrity, and rejects any
  enabled privilege other than `SeChangeNotifyPrivilege` (`BrokerLogonToken.cpp:194-431`). It
  deliberately does not disable SIDs or add restricting SIDs: the account is already
  non-administrative, and the separate `LogonUserW` logon SID—not token restriction—is the
  isolation control that removes the caller's process-DACL match. The elevated provisioning test
  asserts Medium integrity and the enabled-privilege contract; run it from an elevated desktop to
  confirm the real local-account path.

**2 — legacy direct-launch API.** `CreateTerminalPipePair` (`TerminalBridge.cpp:138-209`),
`TerminalBridge::Initialize` (`:310-372`), `PrepareChildProcessCreation` (`:424-466`),
`CompleteChildProcessCreation` (`:468-514`), plus declarations at `TerminalBridge.h:36,39,40`
and the three `child*_` members at `:51-53` with `childHandlesInheritable_` at `:61`.
The only callers are `tests/PseudoConsoleTests.cpp:35,75,90,168,199,216,225` and
`tests/TerminalDisconnectTests.cpp:131,157,174,185`; production uses `InitializeForBroker` only
(`LaunchProcess.cpp:139`). This matters for security: `PrepareChildProcessCreation` sets
`HANDLE_FLAG_INHERIT` **process-wide**, and the tests then call `CreateProcessW` with
`bInheritHandles = TRUE` and **no** `PROC_THREAD_ATTRIBUTE_HANDLE_LIST`. Confined to tests
today, but the API invites a production caller to reintroduce it.
`tests/BrokerTerminalBridgeTests.cpp:33,135` shows how to port.

**3 — response parsers.** FIXED. `ParseResponse` now validates the five common response fields
(version, request ID, status, reason code, and Win32 error); each public parser supplies only its
payload-field validation. The focused protocol regression confirms an otherwise valid response
with an unexpected field is still rejected.

**4 — `LocalFree` wrappers.** FIXED. The shared `LocalAllocation<T>` beside `UniqueHandle`
owns LocalAlloc-family results, including APIs that receive an allocated pointer through an output
parameter. Readable typed aliases now replace the eight local wrappers.

**5 — test assertions.** FIXED. The repeated native-test `Expect()` helper now lives in
`tests/TestSupport.h`; all matching test files include that single definition.

**7 — dead branches.** FIXED. The console-launch fallback now follows the management branch
directly; unreachable console reason arms and the unused `InvalidJson` parse result are gone.
The write-only caller integrity-level probe was removed while the live `TokenElevation` check
remains the management-operation authorization control.

**8 — dead exports.** FIXED with item 11. The unused
`GetLauncherExecutablePath` and `BuildPseudoConsoleHostArguments` exports were removed with the
obsolete client self-hosting path.

**8/11 — unlink ConPTY from the client.** FIXED. `launch_as.exe` no longer links the
`PseudoConsoleHost`/`PseudoConsoleSession` implementation or accepts the internal host switch;
only `launch-as-conhost.exe` hosts a pseudoconsole. The terminal-disconnect test now targets that
dedicated binary, and the behavior suite confirms the client rejects the removed switch.

### Test-coverage hole

`CMakeLists.txt:547-568` builds `LauncherBrokerAccountProvisioningTests` with five `src/`
modules, but there is still **no `add_test`** for it — 286 lines of tests for account
provisioning, the code that decides account eligibility (i.e. S3), compile on every build and
never run. Register it rather than delete it.

The rework did fix the labelling half of this: every registered test now declares `LABELS`
(`broker;unit`, `broker;integration`, `launcher;unit`, `launcher;integration;terminal`,
`setup;unit`, `launcher;behavior`). But `build.ps1:105` still filters with
`--label-exclude 'elevated|interactive'`, and no test uses either label, so the filter remains a
no-op and README's "every non-elevated test" is enforced by nothing. The three
`Invoke-*AcceptanceTest.ps1` scripts are unregistered instead. Labelling the provisioning tests
`broker;elevated` and registering them would be the filter's first real use.

  `BrokerProtocol.cpp:454-479` escapes everything outside `0x20..0x7E` as `\uXXXX`). One wire
  format should not have two encoders.
- **`AppendUtf8` names two unrelated functions** (`BrokerControlClient.cpp:22-46` converts
  wide → UTF-8; `BrokerProtocol.cpp:223-247` appends a code point), and there are **six**

- `TemporaryDirectory` exists in 5 test files (`BrokerAccountProvisioningTests.cpp:55`,
  `BrokerCallerPolicyTests.cpp:16`, `BrokerDataDirectoryTests.cpp:17`,
  `BrokerEnrollmentStoreTests.cpp:16`, `BrokerServiceInstallerTests.cpp:66`), three differing
  only in a name literal.
- `tests/CommandLineTests.cpp:21-40` reimplements `UniqueHandle` (no move, no `reset()`, no

### Suspicions that proved unfounded

- **Version-resource templates are not duplicated.** There is one
  `resources/LauncherVersion.rc.in`, now stamped four times by
  `configure_launch_as_version_resource()` (`CMakeLists.txt:22-56`) — the fourth for the new
  `launch-as-admin`. The `.rc` files are generated outputs in `out/build/`. Already optimal.
- **`launch-as-conhost.exe` and `launch-as-admin.exe` are justified as separate binaries.** The
  installer copies only the broker and conhost into `%ProgramFiles%\launch-as`
  (`BrokerServiceInstaller.cpp:366-379`); merging would drag user-facing code into the protected
  directory. Splitting the elevated admin CLI out of the client is a clear improvement over the
  previously reviewed single binary. The waste is item 11, not the separate executables.
- **`LaunchProcess.cpp` is not vestigial.** It is the live broker client path
  (`InitializeForBroker` → `LaunchBrokerConsole` → `ConnectBrokerChild`); no
  `CreateProcessWithLogonW` remains anywhere in `src/`. Only the name is stale, and
  `AGENTS.md:5` still cites it as the exemplar module.
- **`FormatWindowsError` has zero duplicates** — one declaration, one definition,
  `FormatMessageW` appears nowhere else, and every diagnostic in `src/` reuses it. This is
  the model the rest of the codebase should follow.
- **`out/` is not tracked.** `.gitignore` is exactly `out/`. Deleting the four release zips in
  the repository root (`v0.3.0`, `v0.3.1`, `v0.3.2`, `v1.0.0-preview`) frees ~1.2 MB of local
  disk with no repo impact.

## Documentation defects

- **`README.md:59` and `CHANGELOG.md:9-10` now contradict the code and the spec.** Both state
  that "an enrolled account runs one session at a time" and "a second launch fails immediately".
  The implementation admits two per account and four globally
  (`BrokerServiceRuntime.cpp:36-37`), the spec documents exactly that (`§10:305-311`,
  `§9:259-263`), and `Invoke-BrokerSameAccountConcurrencyTest.ps1` asserts it. This is the
  mirror image of the mismatch the earlier review withdrew: the code moved, the spec followed,
  the user-facing docs did not. Fix the README and add a `1.0.0-preview` changelog line for
  bounded multi-session support.
- `README.md:7` — "The current stable version is still **v3.2.0**" and
  "[Browse the stable **v3.2.0** version]" should both read **v0.3.2**; the link target is
  already correct.
- `discovery/Spike - parallel sessions.md` is now *mostly* implemented — the per-profile session
  registry and the multi-session dispatcher it asks for exist. Its **Password model** section
  (`:13-21`) still recommends generating the password once at enrollment and storing it in a
  service-only secret store, which is the opposite of the implemented per-launch rotation
  (`BrokerServiceRuntime.cpp:507-522`) and of spec `§10:301-304`. Mark that section superseded
  rather than deleting the file.
- `discovery/Spike - Task Scheduler as Broker Replacement for Console.md` (346 lines) evaluates
  a rejected design. Archive it.
- `src/LicenseHeader.cpp:28-29` — the GPL redistribution notice is commented out, so the
  banner states the warranty disclaimer but not the redistribution terms.
- Spec `§17:440` still lists "Phase 1 validates existing absolute executable and
  working-directory paths" as a threat-sensitive invariant. `§9:254-257` now correctly

  documented design — but an invariant enforced only outside the trust boundary should say so.

## What is solidly built

Worth recording so it is not disturbed by later refactors:

- **Password generation** (`BrokerPassword.cpp`) is the strongest code in the repo:
  `BCryptGenRandom(BCRYPT_USE_SYSTEM_PREFERRED_RNG)` with textbook **rejection sampling**
  (`:40-58`, no modulo bias), 32 characters over a 68-character alphabet (~195 bits), one
  guaranteed character per class followed by a full Fisher-Yates shuffle (`:111-138`),
  confusable characters excluded, every RNG failure propagated with no fail-open fallback,
  `SecureZeroMemory` (not `memset`), copy construction deleted (`BrokerPassword.h:21-22`).
- **No secret leaves the process**: never on a command line, never in an environment block,
  never in the audit record.
- **Authorisation uses the impersonation token, not the PID.** `ImpersonateNamedPipeClient`
  → `OpenThreadToken(OpenAsSelf = TRUE)` → immediate `RevertToSelf`
  (`BrokerPipeServer.cpp:161-175`); impersonation failure is a hard denial. The
  `GetNamedPipeClientProcessId` path (`:255-292`) is a *secondary* equality requirement that
  can only deny, so the PID-reuse/TOCTOU hazard is fail-closed. Management operations
  additionally require elevation, and `launch` can never reach them
  (`BrokerProtocol.cpp:501-504`).
- **The launch gate is explicit.** `LaunchProfile` serialises password reset → `LogonUserW` →
  process-wide privilege changes → `ResumeThread` under one mutex, and management operations take
  the same mutex, so concurrency was added without reopening the reset/logon race
  (`BrokerServiceRuntime.cpp:443,506`).
- **The new IPC is properly cancellable.** Every read, write, child wait, and accept is
  overlapped and waits on `stopEvent` alongside its own event, with `CancelIoEx` +
  `GetOverlappedResult(…, TRUE)` on every abandon path — no orphaned overlapped structures
  (`BrokerPipeServer.cpp:22-157`, `BrokerServiceRuntime.cpp:374-413`). The worker-slot wait
  is `static_assert`ed against `MAXIMUM_WAIT_OBJECTS` (`:39`).
- **No handle passing.** `bInheritHandles = FALSE` at every production `CreateProcess*`; no
  `DuplicateHandle` into any client; the response carries only a PID. The client cannot
  obtain the logon token, the job, or the broker's process handle.
- **Job lifetime is correct.** `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` set before any process
  exists and the job discarded if the limit cannot be applied
  (`BrokerProcessLauncher.cpp:308-327`); child created `CREATE_SUSPENDED` → assigned →
  logon-SID-validated → only then resumed (`BrokerServiceRuntime.cpp:547-565`). The job is
  unnamed with a non-inheritable handle, and no breakaway flags are set.
- **`lpApplicationName` is always the broker's own conhost**, resolved from
  `GetModuleFileNameW` and existence-checked (`BrokerProcessLauncher.cpp:141-167`), with client
  arguments strictly after `--` — no option or argv[0] injection.
- **Parser hardening.** Non-recursive (no stack exhaustion), duplicate-key rejecting, 64 KiB
  message cap at both transport and parse layers, 64-argument and 8 KiB-per-argument caps,
  surrogate-pair validation, `MB_ERR_INVALID_CHARS`, `from_chars` with
  `result_out_of_range` handling. `requestId` validated as a strict 36-character GUID.
  Console pipe names constrained to `\\.\pipe\launch-as-*`, no further separators, mutually
  distinct (`BrokerProtocol.cpp:740-748`) — which is what blocks the confused-deputy attack.
- **`ValidateChildLogonSid`** (`BrokerProcessLauncher.cpp:544-567`) enforces the Surface-2
  invariant before `ResumeThread`, failing closed when no logon SID is present and rejecting a
  child that shares the caller's logon SID.
- **Enrollment store mechanics**: write-temp → `FlushFileBuffers` → `MoveFileExW` atomic
  replace, with magic/version/`SECURITY_MAX_SID_SIZE`/`GetLengthSid` validation on read.
- **Service installation**: binary path is quoted (`BrokerServiceInstaller.cpp:474`, no
  unquoted-path escalation); `%ProgramFiles%\launch-as` is `PROTECTED_DACL` with Users at
  read-execute only (`:29`); service DACL grants the caller only `SERVICE_START` (`:440`);
  `DeleteService` rollback on failure (`:526,535`); the Event Log source is registered and
  unregistered symmetrically (`BrokerAudit.cpp:21-53`).
- **Relay threads** are `std::jthread` members, never detached, with `started_` /
  `relaysStarted_` set before creation so a partially-constructed set is still joined; each
  relay owns its own buffer; the resize thread is joined before `ClosePseudoConsole()`. No
  resource leaks were found on any error path in the launch/terminal code.
- **The concurrency acceptance test is unusually good.** It asserts distinct PIDs, distinct
  logon SIDs, rejection of the third same-account launch with the exact reason code and
  `win32Error`, independence of the two sessions under disconnect, and — hardest — that a
  released slot is not reused until the disconnected process tree is actually gone.

The defects are concentrated in the seams — one missing flag, one missing owner reset, one
EOF check, one conditional slot release — not in the design. The multi-session rework was
executed cleanly: it added a real mutex where the previous code relied on single-threading, made
the IPC cancellable throughout, split the elevated administration surface into its own binary,
and shipped an acceptance test that proves the property it claims.
