# launch-as — review: simplicity, complexity, security

Date: 2026-09-11, later the same day · Reviewed tree: current working tree, after the
multi-session rework · Version under review: 1.0.0-preview

Supersedes [REVIEW-2026-09-11.md](REVIEW-2026-09-11.md), which examined the tree as it stood
before the multi-session rework landed and is kept unchanged as the historical record. This is a
standalone review of the current code: every file/line anchor below was re-resolved and every
finding re-read against the on-disk content rather than carried over. Where the rework fixed
something, the finding is kept and marked **RESOLVED** with its residue, so a later refactor
cannot silently reintroduce it.

## Scope and method

Four parallel review tracks over `src/`, `tests/`, `CMakeLists.txt`, the PowerShell
scripts, and the design docs:

1. broker trust boundary (IPC, caller authorisation, untrusted input parsing);
2. credential lifecycle and privileged installation (passwords, ACLs, enrollment, setup);
3. process launch and terminal bridging (ConPTY, job objects, handle inheritance);
4. removable complexity (dead code, duplication, over-generalisation).

### Method caveats

- **No build or runtime verification.** `cmake`, `ninja`, `clang-format`, and the MSVC
  toolchain are all absent from the review environment, and the broker service is not
  installed. Prebuilt binaries under `out/build/` do not match source. Everything except the
  PowerShell quoting defect (item S5, reproduced directly in the earlier review) is confirmed
  by code inspection only.
- **`git` is not on PATH**, so history and tracked-file state could not be queried directly;
  the rework was reconstructed from source, not from a diff. `.gitignore` is exactly `out/`,
  so the release zips and the `out/build/` tree are untracked local artifacts.
- **Physical line counts** (`Measure-Object -Line` skips blank lines; these do not):
  `BrokerProtocol.cpp` 1090, `CMakeLists.txt` 760, `TerminalBridge.cpp` 657,
  `BrokerServiceInstaller.cpp` 656, `BrokerServiceRuntime.cpp` 643,
  `BrokerProcessLauncher.cpp` 569, `BrokerPipeServer.cpp` 406, `PseudoConsoleHost.cpp` 403,
  `BrokerAdminCli.cpp` 305, `PseudoConsoleSession.cpp` 274.

### Effect of the multi-session rework

The earlier review examined a tree in which the multi-session registry had just been reverted.
**It is back, and it is now the specified, implemented, and acceptance-tested design.** What
changed:

- `BrokerServiceRuntime.cpp` grew from 447 to 643 lines. `MaximumConcurrentSessions = 4`,
  `MaximumConcurrentSessionsPerAccount = 2`, `MaximumConcurrentPipeWorkers = 8`
  (`:36-39`), `TryReserveSession`/`ReleaseSession` and the `launchGate` mutex
  (`:109-168`), and a worker pool with overlapped `ConnectNamedPipe` and a bounded wait for a
  free slot (`:258-421`).
- `BrokerPipeServer.cpp` is fully overlapped: every read, write, and child wait is now
  cancellable against `stopEvent`, and the request read has a 5 s timeout
  (`:20-97`). Each connection is served on its own `std::thread`.
- `session_limit_reached` / `ERROR_BUSY` is wired end to end
  (`BrokerPipeServer.cpp:366`, `LaunchProcess.cpp:178-183`).
- New separate `launch-as-admin.exe` target (`CMakeLists.txt:229-265`) with
  `BrokerAdmin.cpp`, `BrokerAdminCli.cpp`, and a real Event Log audit module
  (`BrokerAudit.cpp`). Every ctest registration now carries `LABELS`.
- New acceptance test `tests/Invoke-BrokerSameAccountConcurrencyTest.ps1` (449 lines) proves
  two same-account sessions with distinct logon SIDs, rejection of the third, and that a
  released slot is reused only after the process tree is gone.

**The reset → `LogonUserW` window is still safe, now by an explicit lock rather than by
accident.** `LaunchProfile` holds `policy->launchGate` from before `GenerateBrokerPassword`
through `ResumeThread` (`BrokerServiceRuntime.cpp:506-565`), and `ConfigureProfile` takes the
same gate (`:443`), so enroll/unenroll/list serialise against launches. No reset/logon race was
found. The earlier review's note that "there is now no `std::mutex` anywhere in `src/`" is
obsolete.

Two findings changed grade as a result: **S8** (broker wedge) is now bounded per worker instead
of global, and **C2** (profile unload ordering) is fixed on the production path. One finding was
added: **S12** (session-slot and worker leak on teardown failure), which only exists because
slots exist. And the session-limit documentation mismatch that the earlier review *withdrew* is
back **inverted** — see Documentation defects: `README.md` and `CHANGELOG.md` still promise one
session per account, which is now wrong; the spec is correct.

## Security findings

### S1 — Control-pipe squatting plus full impersonation · HIGH · CONFIRMED --> FIXED

### S2 — `%ProgramData%\launch-as` ownership is never reset · HIGH · CONFIRMED --> FIXED

### S3 — Enrollment records unauthenticated; eligibility is only "not Administrators" · HIGH · CONFIRMED  --> FIXED

### S4 — 735 lines of dead credential code, including a live `CredWriteW` path · MEDIUM · CONFIRMED  --> FIXED

### S5 — `Setup-LaunchAs.ps1` self-elevation breaks on any space in the path · MEDIUM · CONFIRMED (reproduced)

`Setup-LaunchAs.ps1:34-41` passes an **array** to `Start-Process -ArgumentList`, which
joins with spaces and adds no quoting. Reproduced directly in the earlier review; the code is
unchanged:

```
ArgumentList: -NoProfile / -ExecutionPolicy / Bypass / -File / C:\...\Temp\space dir\argprobe.ps1 / ...
stderr: The argument 'C:\...\Temp\space' is not recognized as the name of a script file.
ExitCode: 64
```

So setup cannot self-elevate when the package is extracted anywhere with a space in the
path — `C:\Users\First Last\Downloads\...` is the common case. Security variant: pwsh
attempts to *execute* the truncated path, so a file plantable at the truncation point runs
elevated. `$DefaultAccount` is only `[ValidateNotNullOrEmpty()]` (`:8-9`) and is never checked
against `IsValidBrokerAccountName`, so a value containing a space injects further parameters
into the elevated command line.

Additionally `:40` resolves `pwsh` through `$env:PATH` — user-writable via
`HKCU\Environment` — and then elevates that binary with `-Verb RunAs`.

Fix: pass a single pre-quoted string, resolve pwsh from `$PSHOME`, and constrain
`$DefaultAccount` with `[ValidatePattern]`.

Related (MEDIUM): the elevated script then invokes `launch-as-admin.exe` resolved from
`$PSScriptRoot` or `$PSScriptRoot\out\build\Release` (`:55-65`) with no signature check, from a
user-writable extraction directory, with a `Test-Path` → invoke TOCTOU window (`:57-65` then
`:72`, `:92`, `:103`). `InstallBrokerService` inherits the same assumption: it takes its own
module path and copies the siblings named `launch-as-broker.exe` and `launch-as-conhost.exe`
into `%ProgramFiles%` unverified (`BrokerServiceInstaller.cpp:341-379`). No remote download
anywhere — good. The elevation self-check itself (`:19-23`) uses the correct API.

### S6 — Client-controlled `workingDirectory` resolved as LocalSystem · MEDIUM · CONFIRMED

`src/BrokerProcessLauncher.cpp:338-344` calls `std::filesystem::is_directory()` as
LocalSystem on the raw request string; `BrokerProtocol.cpp:654-660` validates only non-empty and
≤ 32 KiB, with no absolute/UNC/device-path rejection. The value is then passed straight to
`CreateProcessAsUserW` as `lpCurrentDirectory` (`:397`). A UNC value coerces outbound
machine-account SMB authentication (an NTLM-relay primitive) and gives an existence oracle
over SYSTEM's view of the filesystem. The client-side check at `LaunchProcess.cpp:110-132`
is irrelevant — the client is the attacker.

Fix: in the broker, reject non-`is_absolute`, UNC (`\\`), and `\\?\` / `\\.\` prefixed
paths, and canonicalise before use.

### S7 — `ResizePseudoConsole` unbounded and unthrottled · MEDIUM · CONFIRMED

`src/TerminalIO.cpp:104-116` validates only `X > 0 && Y > 0`, and
`PseudoConsoleSession.cpp:180-194` feeds the value straight into `api_.resize()` in an
unbounded loop. The resize pipe server is owned by the untrusted client, so
`COORD{32767, 32767}` forces a multi-gigabyte text-buffer allocation, and repeated writes
burn CPU. The *request* path is correctly clamped to 1..32767
(`BrokerProtocol.cpp:417-419`, re-checked at `PseudoConsoleHost.cpp:102-112`) — only the
runtime channel is unguarded. Clamp to a sane maximum and coalesce.

Secondary fragility, downgraded: `ReadTerminalSize` reads a 4-byte struct over a
`PIPE_TYPE_BYTE` pipe, but it now loops through `ReadAll` (`TerminalIO.cpp:33-46`), so a
short write blocks until the rest arrives instead of desynchronising permanently. An
odd-length write still misaligns every subsequent resize frame.

### S8 — Wedged control connections consume the worker pool · MEDIUM · CONFIRMED (rescored)

`src/BrokerPipeServer.cpp:127-157` still waits `INFINITE` for the control connection to close,
now on `{stopEvent, operationEvent}`. The rework removed the global wedge: each connection has
its own worker thread, and the request read is bounded to 5 s
(`:20-29`, `RequestTimeoutMilliseconds`). What remains is a pool-exhaustion DoS. Eight clients
that launch a fast-exiting program, read the exit response, and never close their handles
occupy all eight workers; the accept loop then blocks in `WaitForAvailableWorkerSlot`
(`BrokerServiceRuntime.cpp:325-347`) on an `INFINITE` wait, so no new pipe instance is created
at all — later callers see `ERROR_FILE_NOT_FOUND`, try to start an already-running service, and
fail after the client's 5 s deadline (`BrokerControlPipe.cpp:66-107`). The 30 s idle self-stop
cannot run either, because the accept loop never reaches its timeout branch. Only an SCM stop
recovers. Bound `WaitForControlConnectionClose`, and give the slot wait a timeout so the
service can still self-stop.

### S9 — Password plaintext left in freed heap · MEDIUM · CONFIRMED

`src/BrokerPassword.cpp:97-98`:

```cpp
characters_.assign(first, first + length_);   // MSVC: capacity becomes exactly 32
characters_.push_back(L'\0');                 // reallocates to 48, copies, frees old block unwiped
```

`Clear()` (`:76-84`) wipes only the current buffer, so a plaintext copy of the per-launch
password persists in freed LocalSystem heap until reuse. With up to four concurrent sessions
this now happens up to four times per burst. One-line fix:
`characters_.reserve(length_ + 1)` before `assign`.

### S10 — `%ProgramData%` resolved from the environment · LOW/MEDIUM · CONFIRMED

`src/BrokerDataDirectory.cpp:82-95` uses `GetEnvironmentVariableW(L"ProgramData")`, while the
sibling install path correctly uses `SHGetKnownFolderPath(FOLDERID_ProgramFiles)`
(`BrokerServiceInstaller.cpp:227-239`). An elevated process inherits the requesting shell's
environment, so an over-the-shoulder elevation redirects where `install` writes
`authorized-caller.sid` (`BrokerServiceInstaller.cpp:390-396`). This one fails closed (an empty
SID denies every caller, and the pipe DACL gets no caller ACE), so the impact is a redirected
install-time write plus a confusing DoS, not escalation. Use `FOLDERID_ProgramData`.

### S11 — Lower-severity items · CONFIRMED

- **`enroll` silently re-enables a disabled account.**
  `BrokerAccountProvisioner.cpp:35` clears `UF_ACCOUNTDISABLE`, so enrolling `Guest`,
  `DefaultAccount`, or a disabled ex-employee account resets its password *and* re-enables
  it. Symmetrically, `Unenroll` sets `UF_ACCOUNTDISABLE` unconditionally
  (`BrokerRegistration.cpp:110-111`), leaving a pre-existing account disabled with a lost
  password. Spec `§11:339-341` calls for mode-aware teardown; not implemented.
- **`unenroll` of one account stops every account's sessions.** `BrokerAdminCli.cpp:238-247`
  (and `:276-282` for `unenroll-all`) calls `StopBrokerService()` before forwarding the
  request, which stops the service and so closes every kill-on-close job — including live
  sessions of unrelated enrolled accounts. The consent prompt at `:227-234` describes only the
  named account. This is the placeholder for the per-profile draining that spec `§22:603-605`
  still lists as open; until then, say so in the prompt.
- **`IsProfileId` omits control-character rejection.** `BrokerProtocol.cpp:304-309` shares
  a byte-identical forbidden-character literal with `IsValidBrokerAccountName`
  (`BrokerAccountProvisioner.cpp:103-111`) but drops the `>= L' '` check, so the wire layer
  accepts a `profileId` containing `\n` that the provisioner rejects. Traced to all
  consumers: the stricter check runs on every account path, so no traversal or
  NUL-desynchronisation is reachable today. It does, however, now reach `TryReserveSession`
  (`BrokerServiceRuntime.cpp:501`) as a map key before any account validation. Worth aligning.
- **`RevertToSelf` failure returns while still impersonating.**
  `BrokerPipeServer.cpp:169-175` returns `false` without a retry or fail-fast. The rework
  reduced the blast radius — the thread is now per-connection rather than the single loop
  thread — but a leaked impersonation on a thread that then runs the worker's teardown still
  warrants an abort.
- **`GW` in the pipe DACL grants `FILE_CREATE_PIPE_INSTANCE`.**
  `BrokerServiceRuntime.cpp:207-225` emits `(A;;GRGW;;;<callerSid>)`; on a named pipe the
  generic-write mapping includes instance creation. Not the squat enabler (S1 is), but the
  grant should state an explicit mask.
- **Audit-field injection.** `BrokerServiceRuntime.cpp:190-205` interpolates the raw
  `profileId` into `account=…` before account-name validation. `=` is banned and fields are
  separate `ReportEventW` insertions (`BrokerAudit.cpp:55-89`, which additionally rejects
  embedded NULs), so this is log pollution only.
- **Terminal-pipe DACL built by SDDL concatenation.** `TerminalBridge.cpp:95-99` splices
  `childSid` into a string; safe today because the SID always comes from
  `ConvertSidToStringSidW` (`LaunchProcess.cpp:97`). Validate or build the ACL programmatically.
- **`std::wstring_view::data()` passed to `...W` APIs.** `BrokerDataDirectory.cpp:60,69`,
  `BrokerServiceInstaller.cpp:109,130,139,150`, `PseudoConsoleHost.cpp:182`. Safe only
  because every current caller passes a `std::wstring`; latent OOB read on a SYSTEM path.
- **Missing hardening.** No `SERVICE_CONFIG_REQUIRED_PRIVILEGES` or
  `SERVICE_SID_TYPE_RESTRICTED` on the service (`BrokerServiceInstaller.cpp:399-540` sets only
  description and DACL); no `/guard:cf`, `/Qspectre`, `/CETCOMPAT`, or `/DEPENDENTLOADFLAG` in
  `configure_launch_as_target` (`CMakeLists.txt:104-113`), though `/sdl /W4 /WX` are on.
- **`CreateRestrictedToken` (spec `§12:353`, step 6) is not implemented.** The token from
  `LogonUserW` is a full primary token with default groups and DACL.

### S12 — A failed teardown leaks a session slot and its worker, permanently · MEDIUM · NEW

Two coupled unbounded paths, both introduced with the session registry:

1. `BrokerPipeServer.cpp:395-399` releases the slot only when
   `sessionStarted && processTreeExited && handler != nullptr`.
   `BrokerChildProcess::TerminateAndWaitForExit` returns `false` whenever
   `QueryInformationJobObject` fails or termination failed with processes still active
   (`BrokerProcessLauncher.cpp:227-256`), so `FinishProfileSession` never runs and
   `sessionCount`/`sessionsByAccount` are never decremented. Four such failures and every
   launch returns `session_limit_reached` until the service is stopped. Slot accounting is
   deliberately conservative — the acceptance test at
   `Invoke-BrokerSameAccountConcurrencyTest.ps1:418-422` asserts a slot is *not* reused before
   the tree exits — but "conservative" must not mean "never".
2. The same function's drain loop (`BrokerProcessLauncher.cpp:229-254`) is unbounded: after a
   successful `TerminateJobObject` it does `WaitForSingleObject(process_, INFINITE)` and then
   polls `ActiveProcesses` with `Sleep(10)` forever. A process stuck in an uninterruptible
   kernel wait parks the worker thread permanently, which also costs one of the eight pool
   slots (S8) and blocks service stop, since `JoinWorkers` (`BrokerServiceRuntime.cpp:275-285`)
   joins unconditionally.

Fix: give the drain a deadline, and release the session slot on a `finally`-equivalent path —
reporting an audit event when the tree could not be confirmed dead — rather than making the
release conditional on success.

## Correctness findings

### C1 — Redirected stdin EOF kills the target and misreports the exit code · HIGH · CONFIRMED

Chain, confirmed at every step against current line numbers:

1. `src/TerminalIO.cpp:60-66` — `if (!ReadFile(...) || bytesRead == 0) return;` treats EOF
   as indistinguishable from an error.
2. `src/TerminalBridge.cpp:555,560-562` — the input pipe-server handle is **moved into** the
   relay lambda, so it is closed the instant `RelayInput` returns.
3. The conhost's read then fails → `PseudoConsoleSession.cpp:166-167` →
   `SetEvent(inputRelayCompleteEvent_)`.
4. `src/PseudoConsoleHost.cpp:307-332` — the event wins the wait →
   `TerminateProcess(process, ExitCancelled)` → returns 1223, which the broker relays as the
   child's exit code (`BrokerPipeServer.cpp:378-385` → `LaunchProcess.cpp:215-224`).

Repro:

```powershell
echo hi | launch-as.exe --user LaunchAsUser -- C:\Windows\System32\cmd.exe /c "timeout /t 5 & exit 7"
```

The client's stdin EOFs immediately, the target is killed within milliseconds, and the
caller sees **1223**, not 7. This blocks every pipeline, script, and CI use — the
automation case the README describes. Interactive use is unaffected, which is why
acceptance testing missed it.

The test suite is one line from catching it: `tests/TerminalDisconnectTests.cpp:107-119` and
`tests/PseudoConsoleTests.cpp:143-153` already redirect stdin to a pipe, but hold the write
end open. Closing it and asserting the child's exit code reproduces the bug.

Fix: distinguish EOF from error in `RelayInput`, and do not treat client-stdin EOF as a
session-cancel signal — the disconnect signal should be the control or output pipe.

### C2 — `UnloadUserProfile` before job kill · RESOLVED on the production path · residual LOW

The earlier review reported that `BrokerChildProcess::Reset()` unloads the user profile before
closing the kill-on-job-close handle, leaving a stale `HKU\<SID>` hive per session. The ordering
inside `Reset()` is unchanged (`BrokerProcessLauncher.cpp:259-286`: unload at `:263`, job close
at `:279`), but it is no longer reached with a live child: `TerminateAndWaitForExit`
(`:219-257`) now terminates the job, waits for the host process, polls
`JobObjectBasicAccountingInformation` until `ActiveProcesses == 0`, and only then calls
`Reset()` — and `ServeControlPipeRequest` always routes through it (`BrokerPipeServer.cpp:395`).
The earlier related LOW ("`Reset()` never waits for the job to drain") is answered by the same
loop; its cost is the unbounded wait now tracked as S12.

Residual: `Reset()` is still publicly reachable with a live process — `LaunchProfile` calls it
directly when `ValidateChildLogonSid` fails (`BrokerServiceRuntime.cpp:557`). That child is
`CREATE_SUSPENDED` and has never touched `HKCU`, so the unload succeeds today; the safety is
incidental, not structural. Move the drain into `Reset()`, or make the unload-after-drain
ordering explicit there.

### C3 — Exit codes and diagnostics are jointly unusable in broker mode · MEDIUM · CONFIRMED

`LauncherOptions.h:19-22` defines `ExitFailure = 1`, `ExitUsage = 87`,
`ExitCancelled = 1223`, while `LaunchProcess.cpp:224` and `PseudoConsoleHost.cpp:359` pass
through the child's raw `DWORD`. Every conhost-internal failure returns `ExitFailure`, so
"the bridge broke" and "your program returned 1" are the same observable. With C1, 1223 is
ambiguous between "cancelled" and "the program returned 1223".

Worse, `PseudoConsoleHost.cpp:234` passes `redirectDiagnostics = !brokerPipes`, so the
stderr redirect is skipped in broker mode — and the conhost is created with a plain
`STARTUPINFOW` (`BrokerProcessLauncher.cpp:367-368`: no `STARTF_USESTDHANDLES`, plus
`CREATE_NO_WINDOW` and `bInheritHandles = FALSE` at `:394-395`), so it has no valid std handles
at all. Every diagnostic `std::wcerr` in `RunPseudoConsoleHost` goes nowhere; a failed launch
surfaces as bare "exited 1". `PseudoConsoleHost.cpp:236` also writes to `std::wcout`, injecting
launcher prose into the client's terminal byte stream.

`STILL_ACTIVE` (259) is not a live risk — both `GetExitCodeProcess` calls are reached only
after the process handle signalled.

### C4 — `TerminalBridge::Stop()` can block forever on the console read · MEDIUM · PLAUSIBLE

`src/TerminalBridge.cpp:618-622`. The input relay blocks in `ReadFile` on the console input
handle, and `CancelSynchronousIo` does not cancel a blocking console read. `Stop()` is
`noexcept` and also the destructor path (`:308`), so the client hangs after the session ends
until a key is pressed. The output relay correctly force-unblocks via `DisconnectNamedPipe`
after a grace period (`:625-638`); there is no equivalent escape for the console read.

### C5 — `GetLastError()` read after intervening calls · LOW (house rule) · CONFIRMED

`src/LaunchProcess.cpp:204-211` reads `GetLastError()` after `terminalBridge.Stop()` (which
performs `CancelSynchronousIo`, thread joins, `CloseHandle`, `SetConsoleMode`,
`SetConsoleCP`) and `connection.Reset()`, so the reported value is unrelated. This violates
`AGENTS.md:38-43`. Structurally, `TerminalBridge::WaitForOutput()` should capture and return
the `DWORD` itself.

This is the **only** violation across the launch/terminal surface; the surrounding code
consistently captures the error immediately, including the
`AdjustTokenPrivileges`-succeeds-with-`ERROR_NOT_ALL_ASSIGNED` idiom at
`BrokerProcessLauncher.cpp:64-80` and every new overlapped path in `BrokerPipeServer.cpp`.

### C6 — `BuildWindowsCommandLine` escapes argv[0] with argument rules · LOW · CONFIRMED, not reachable

`src/WindowsCommandLine.cpp:54` runs the executable through
`QuoteWindowsCommandLineArgument`, but argv[0] is parsed by different rules (backslashes are
not escapes; the token ends at the first closing quote). Measured against the real
`CommandLineToArgvW`, `C:\a"b\p.exe` yields merged and injected arguments. Not currently
reachable: both call sites gate on `is_absolute() && is_regular_file()`
(`PseudoConsoleHost.cpp:245-252`, `BrokerProcessLauncher.cpp:155-163`), a `"` cannot appear
in an NTFS filename, and `CreateProcess*` is always called with an explicit
`lpApplicationName`. Worth fixing because the helper is generic and the guard is incidental.

**The argument path is correct**: 20 000 randomized round-trips through the real
`CommandLineToArgvW` passed with zero failures, covering trailing backslashes before a
quote, `\\\"` runs, embedded quotes, empty and whitespace-only arguments, and tabs. The
`tests/CommandLineTestArguments.h` set (8 vectors) covers empty, whitespace-only (`L"\t"`),
embedded quote, trailing backslashes, and backslash-quote; it still misses a bare `"`, a bare
`\`, and a leading-quote argument — cheap additions.

### C7 — Minor

- `PseudoConsoleHost.cpp:297` checks `ResumeThread(...) == (DWORD)-1` while
  `BrokerChildProcess::Resume` (`BrokerProcessLauncher.cpp:204-217`) correctly requires
  `== 1`; the weaker check misses a thread that was not actually suspended.
- `TerminalBridge.cpp:573-586` — the resize thread polls on a 200 ms sleep, so `Stop()` pays
  up to 200 ms and resizes lag; a failed `SendResize` silently returns, permanently
  disabling resize with no diagnostic.
- `PseudoConsoleSession.cpp:106-110` sets `STARTF_USESTDHANDLES` with all three handles
  `nullptr`; harmless because `PROC_THREAD_ATTRIBUTE_PSEUDOCONSOLE` overrides, but it is an
  undocumented-behaviour dependency.
- `BrokerServiceRuntime.cpp:296-318` starts the worker `std::thread` *before*
  `workers.push_back(std::move(worker))`. If that `push_back` throws, the running thread's
  captured `workerState` dangles and a joinable `std::thread` is destroyed — `std::terminate`.
  Reserve the vector once outside the loop (it is bounded at 8) or push a placeholder first.
  These worker threads are also the only raw `std::thread`s in the codebase; everything else is
  `std::jthread`.
- `BrokerProcessLauncher.cpp:444-510` (`LaunchFixedBrokerProbe`, test-only) passes
  `lpEnvironment = nullptr` and `lpCurrentDirectory = nullptr`, so the child inherits
  LocalSystem's environment and CWDs into `system32`. Fine for a probe; do not copy the pattern.

## What is solidly built

Worth recording so it is not disturbed by later refactors:

- **Password generation** (`BrokerPassword.cpp`) is the strongest code in the repo:
  `BCryptGenRandom(BCRYPT_USE_SYSTEM_PREFERRED_RNG)` with textbook **rejection sampling**
  (`:40-58`, no modulo bias), 32 characters over a 68-character alphabet (~195 bits), one
  guaranteed character per class followed by a full Fisher-Yates shuffle (`:111-138`),
  confusable characters excluded, every RNG failure propagated with no fail-open fallback,
  `SecureZeroMemory` (not `memset`), copy construction deleted (`BrokerPassword.h:21-22`).
- **No secret leaves the process**: never on a command line, never in an environment block,
  never in the audit record.
- **Authorisation uses the impersonation token, not the PID.** `ImpersonateNamedPipeClient`
  → `OpenThreadToken(OpenAsSelf = TRUE)` → immediate `RevertToSelf`
  (`BrokerPipeServer.cpp:161-175`); impersonation failure is a hard denial. The
  `GetNamedPipeClientProcessId` path (`:255-292`) is a *secondary* equality requirement that
  can only deny, so the PID-reuse/TOCTOU hazard is fail-closed. Management operations
  additionally require elevation, and `launch` can never reach them
  (`BrokerProtocol.cpp:501-504`).
- **The launch gate is explicit.** `LaunchProfile` serialises password reset → `LogonUserW` →
  process-wide privilege changes → `ResumeThread` under one mutex, and management operations take
  the same mutex, so concurrency was added without reopening the reset/logon race
  (`BrokerServiceRuntime.cpp:443,506`).
- **The new IPC is properly cancellable.** Every read, write, child wait, and accept is
  overlapped and waits on `stopEvent` alongside its own event, with `CancelIoEx` +
  `GetOverlappedResult(…, TRUE)` on every abandon path — no orphaned overlapped structures
  (`BrokerPipeServer.cpp:22-157`, `BrokerServiceRuntime.cpp:374-413`). The worker-slot wait
  is `static_assert`ed against `MAXIMUM_WAIT_OBJECTS` (`:39`).
- **No handle passing.** `bInheritHandles = FALSE` at every production `CreateProcess*`; no
  `DuplicateHandle` into any client; the response carries only a PID. The client cannot
  obtain the logon token, the job, or the broker's process handle.
- **Job lifetime is correct.** `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` set before any process
  exists and the job discarded if the limit cannot be applied
  (`BrokerProcessLauncher.cpp:308-327`); child created `CREATE_SUSPENDED` → assigned →
  logon-SID-validated → only then resumed (`BrokerServiceRuntime.cpp:547-565`). The job is
  unnamed with a non-inheritable handle, and no breakaway flags are set.
- **`lpApplicationName` is always the broker's own conhost**, resolved from
  `GetModuleFileNameW` and existence-checked (`BrokerProcessLauncher.cpp:141-167`), with client
  arguments strictly after `--` — no option or argv[0] injection.
- **Parser hardening.** Non-recursive (no stack exhaustion), duplicate-key rejecting, 64 KiB
  message cap at both transport and parse layers, 64-argument and 8 KiB-per-argument caps,
  surrogate-pair validation, `MB_ERR_INVALID_CHARS`, `from_chars` with
  `result_out_of_range` handling. `requestId` validated as a strict 36-character GUID.
  Console pipe names constrained to `\\.\pipe\launch-as-*`, no further separators, mutually
  distinct (`BrokerProtocol.cpp:740-748`) — which is what blocks the confused-deputy attack.
- **`ValidateChildLogonSid`** (`BrokerProcessLauncher.cpp:544-567`) enforces the Surface-2
  invariant before `ResumeThread`, failing closed when no logon SID is present and rejecting a
  child that shares the caller's logon SID.
- **Enrollment store mechanics**: write-temp → `FlushFileBuffers` → `MoveFileExW` atomic
  replace, with magic/version/`SECURITY_MAX_SID_SIZE`/`GetLengthSid` validation on read.
- **Service installation**: binary path is quoted (`BrokerServiceInstaller.cpp:474`, no
  unquoted-path escalation); `%ProgramFiles%\launch-as` is `PROTECTED_DACL` with Users at
  read-execute only (`:29`); service DACL grants the caller only `SERVICE_START` (`:440`);
  `DeleteService` rollback on failure (`:526,535`); the Event Log source is registered and
  unregistered symmetrically (`BrokerAudit.cpp:21-53`).
- **Relay threads** are `std::jthread` members, never detached, with `started_` /
  `relaysStarted_` set before creation so a partially-constructed set is still joined; each
  relay owns its own buffer; the resize thread is joined before `ClosePseudoConsole()`. No
  resource leaks were found on any error path in the launch/terminal code.
- **The concurrency acceptance test is unusually good.** It asserts distinct PIDs, distinct
  logon SIDs, rejection of the third same-account launch with the exact reason code and
  `win32Error`, independence of the two sessions under disconnect, and — hardest — that a
  released slot is not reused until the disconnected process tree is actually gone.

The defects are concentrated in the seams — one missing flag, one missing owner reset, one
EOF check, one conditional slot release — not in the design. The multi-session rework was
executed cleanly: it added a real mutex where the previous code relied on single-threading, made
the IPC cancellable throughout, split the elevated administration surface into its own binary,
and shipped an acceptance test that proves the property it claims.
